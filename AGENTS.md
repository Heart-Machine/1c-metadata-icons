# AGENTS.md — Иконки метаданных 1С

## Назначение

Собственные иконки видов метаданных 1С:Предприятие 8 для любых конфигураций, например для дерева метаданных. Сейчас нарисованы виды, у которых нет стандартной картинки в `БиблиотекаКартинок`. Владелец планирует полный набор в одном стиле, включая виды со стандартными картинками: справочники, документы, регистры и т. п. Полный план — [icons.json](icons.json).

В конфигурацию иконки попадают как общие картинки. Имя (поле `picture` в `icons.json`) — «Метаданные» плюс вид метаданных в единственном числе: `МетаданныеРоль`, `МетаданныеWebСервис`. Префикс `--prefix` добавляется перед ним при выгрузке. «Метаданные» в имени — решение владельца: будущие `МетаданныеСправочник` и `МетаданныеДокумент` не совпадут со стандартными `Справочник` и `Документ`. Ни одна из 295 стандартных картинок `БиблиотекаКартинок` (справка EDT 2026.2) не начинается с «Метаданные». Автор и лицензия указываются в комментарии `.mdo`.

## Стиль

- Плоские цветные иконки. Контур 1 px на сетке 16×16 (координаты линий на `.5`), 2 px на сетке 32×32; заливки по целым пикселям.
- Палитра:
  - синий: контур `#2B6CB0`, тёмный `#23599A`, заливка `#3B82C4`, светлая `#D3E5F8`;
  - оранжевый: контур `#C9711A`, акцент `#E07B1F`, заливка `#F2A03D`, светлая `#FCE0BD`;
  - жёлтый: контур `#B8860B`, заливка `#F5C33B`, светлая `#FDEBB0`;
  - зелёный: контур `#237A45`, заливка `#2F9E5A`;
  - коричневый: контур `#8E5E2C`, заливка `#D9A35F`, средняя `#E8BE84`, светлая `#F1D7AE`;
  - бирюзовый: контур `#23877A`, светлая `#D3F1EC`;
  - серый (линии, рамки): `#5F6B7A`, сетка таблиц `#A9B4C0` (16) и `#B8C2CC` (32);
  - красный: контур `#A83232`, заливка `#D64545`;
  - фиолетовый `#8250C4` — акцент.
- Тёмно-синий `#23599A` годится только для контуров: залитые им крупные фигуры теряются на тёмном фоне.
- Веб-объекты (`web_service`, `http_service`, `ws_reference`, `web_socket_client`, `integration_service`) — глобус слева сверху и белая плашка справа снизу со своим значком: шестерёнка, стрелки запрос-ответ, стрелка «внешняя ссылка», вилка, конверт.
- Метафоры остальных иконок:
  - `configuration` — жёлтый шар;
  - `common` — три цветных блока;
  - `subsystem` — оранжевое дерево узлов;
  - `common_module` — лист с цветными строками кода;
  - `session_parameter` — синий ромб (параметр) с человеком;
  - `role` — ключ;
  - `common_attribute` — два поля реквизита;
  - `event_subscription` — лист модуля с молнией;
  - `functional_option` — переключатель;
  - `functional_option_parameter` — переключатель с ромбом параметра;
  - `defined_type` — буква «T»;
  - `common_command` — кнопка «пуск»;
  - `command_group` — папка с «пуском»;
  - `common_template` — табличный макет;
  - `xdto_package` — посылка;
  - `bot` — голова робота;
  - `palette_color` — палитра художника;
  - `style_item` — цветовой круг;
  - `style` — буква «A» с цветовым кругом;
  - `language` — две реплики, на синей буква «A»;
  - `document_numerator` — лист с цифрами 1, 2, 3 лесенкой (пиксельные глифы 3×5);
  - `sequence` — три стрелки лесенкой: синяя, зелёная, красная.
- Перед сборкой стоит проверить, что графика не выходит за холст: контуры кривых легко уходят за 0 (так было с `palette_color`).

## Структура и сборка

- `src/16/<имя>.svg` — исходник под 14, 16 и 20 px; `src/32/<имя>.svg` — под 24–64 px. Если исходник один, он используется для всех размеров.
- `npm install`, затем `npm run build` ([scripts/build.mjs](scripts/build.mjs), рендер через `@resvg/resvg-js`):
  - `dist/png/<размер>/<имя>.png` — 14, 16, 20, 24, 28, 32, 48, 64 px;
  - `dist/1c/<имя>.zip` — архив картинки 1С: PNG-варианты и `manifest.xml` с плотностями `bldpi`…`udpi` (85–400%) и размерами `glyphWidth`/`glyphHeight`, как в zip-картинках, которые сохраняет 1С; zip без сжатия;
  - `dist/preview.html` — превью (открывать в обычном браузере, пути к PNG относительные);
  - `docs/preview.svg` — превью для GitHub, вставлено в README. Этот файл коммитится вместе с изменениями иконок.
- В `docs/preview.svg` иконки встроены векторными `<symbol>` и выводятся через `<use>`, файл весит около 47 КБ. GitHub не показывает HTML из репозитория, поэтому превью сделано в SVG. Внешних файлов и data-URI в нём нет: для raw-файлов GitHub отдаёт заголовок CSP, который может их заблокировать. Ширина 800 px подобрана так, чтобы README не уменьшал картинку и иконки 16 px оставались чёткими.
- Варианты картинки 1С (плотность, масштаб, размер, сетка исходника) заданы в [scripts/variants.mjs](scripts/variants.mjs), их берут `build.mjs` и `site.mjs`.
- `npm run site` ([scripts/site.mjs](scripts/site.mjs)) собирает иконки и сайт для GitHub Pages в `dist/site`. Адрес — https://heart-machine.github.io/1c-metadata-icons/. Состав согласован с владельцем 15.10.2026:
  - галерея из `icons.json` с поиском по названию вида, имени картинки и файла (без учёта регистра и «ё»), переключатели темы (по умолчанию как в системе) и масштаба 100/125/150/200/300/400% (PNG 16–64 px);
  - карточка открывает панель иконки: увеличенные 16×4 и 32×2, все 8 вариантов на светлом и тёмном фоне, иконка с соседями по `icons.json` в дереве метаданных, скачивание zip-картинки 1С, PNG любого размера и SVG. Адрес `…/#<имя>` открывает панель сразу. Копирование `БиблиотекаКартинок.<картинка>` — на карточке и в панели;
  - «Скачать всё»: картинки 1С, `.cf` и `.cfe` — ссылки `…/releases/latest/download/…`, архив `1c-metadata-icons-png-svg.zip` (PNG, SVG, `LICENSE`, `icons.json`) собирается вместе с сайтом из `main`;
  - автор и CC BY 4.0 в подвале.
- Устройство сайта:
  - `index.html` генерирует `site.mjs`, карточки есть в разметке и без скрипта. `site.css` и `site.js` лежат в [scripts/site](scripts/site) (MIT, как весь `scripts/`) и копируются с хэшем в ссылке: Pages кэширует файлы на 10 минут. Данные об иконках встроены в `<script type="application/json" id="data">`;
  - рядом лежат `png/<размер>/<имя>.png`, `1c/<имя>.zip` и `svg/16|32/<имя>.svg`. Ссылки относительные, поэтому сайт работает и в подкаталоге Pages, и из файла;
  - PNG выводятся пиксель в пиксель: CSS-размер = размер / `devicePixelRatio`, иначе браузер размывает иконку на экранах 125–200%. Масштаб по умолчанию — ближайший к плотности экрана. Дерево в панели всегда в масштабе экрана: при 400% строка с текстом 52 px не помещается;
  - тема и масштаб запоминаются в `localStorage`; без него сайт работает с настройками по умолчанию. Сообщение о копировании — `popover`, чтобы оно было поверх модальной панели `<dialog>`.
- Публикация — [.github/workflows/pages.yml](.github/workflows/pages.yml): `npm ci` и `npm run site` на ubuntu-latest, затем `actions/deploy-pages`. Запускается по пушу в `main`, если изменились `src`, `icons.json`, `scripts`, `package*.json`, `LICENSE` или сам workflow, и вручную. В настройках репозитория Pages → Source: GitHub Actions.
- `npm run export:edt -- [--dry-run] [--prefix <префикс>] <каталог>` ([scripts/export-edt.mjs](scripts/export-edt.mjs)) собирает иконки и пишет их в проект 1C:EDT. Каталог — проект или его `src`, главное, чтобы в нём был `Configuration/Configuration.mdo`. Поддерживается только формат EDT. В проекте скрипт пишет:
  - `CommonPictures/<картинка>/Picture.zip` — обновляется при каждом запуске, другие `Picture.*` в папке удаляются;
  - `<картинка>.mdo` — создаётся только при первом запуске, чтобы сохранить UUID и правки из EDT;
  - строку в `Configuration.mdo` — добавляется с сохранением сортировки без учёта регистра (так EDT сортирует `commonPictures` при сохранении, проверено на 79 картинках `tools_ui_1c`) и CRLF. Если общих картинок ещё нет, список встаёт перед `roles`, `commonTemplates`, `commonModules` и т. п. или после `subsystems`/`languages`.
- Свои картинки скрипт узнаёт по комментарию в `.mdo`. Выгрузка прекращается до любых изменений, и нужно задать `--prefix`, если:
  - одноимённая картинка без такого комментария уже есть;
  - есть картинка, имя которой отличается только регистром. Её ищут по папкам `CommonPictures` и записям в `Configuration.mdo`, причём до обращения к файлам: на Windows путь к `МетаданныеРоль` открыл бы папку `Метаданныероль`.
- `npm run package` ([scripts/package.mjs](scripts/package.mjs)) собирает архив релиза `dist/release/1c-metadata-icons-pictures.zip`. Имя архива без версии, чтобы ссылка `…/releases/latest/download/…` не менялась. Раскладка архива повторяет репозиторий:
  - `README.txt` — из шаблона [release/README.txt](release/README.txt), с подстановкой `{{version}}` и `{{count}}`; в CRLF и с BOM, чтобы читаться в Блокноте;
  - `LICENSE`, `icons.json`;
  - `scripts/export-edt.mjs` с `scripts/LICENSE`;
  - `pictures/<имя>.zip`.
- `export-edt.mjs` берёт картинки из `pictures/` рядом с `icons.json`, а если такой папки нет — из `dist/1c`. Поэтому он работает в распакованном архиве без `npm install`. В нём допустимы только встроенные модули Node.js.
- Zip собирается одной функцией [scripts/zip.mjs](scripts/zip.mjs): stored, с фиксированной датой, так что сборка воспроизводима. В том же модуле `readZip` для проверки `.cf` и `.cfe`.
- `npm run package:1c` ([scripts/build-1c.mjs](scripts/build-1c.mjs)) собирает `dist/release/1c-metadata-icons.cf` и `1c-metadata-icons.cfe`. Это только Windows и только локально: нужны EDT и Конфигуратор, в GitHub Actions их нет. `npm run release` = `package` + `package:1c`. `package:1c` не запускает `build`, потому что `build` стирает `dist/` вместе с архивом релиза. Рабочий каталог — `dist/1c-work`, в нём логи всех шагов.
  - Цепочка: `CREATEINFOBASE` → `/DumpConfigToFiles`. Затем первый запуск `1cedtcli -file`: пустой XML импортируется дважды, в проекты `configuration` и `base`. Затем `export-edt.mjs` в `configuration`, свойства конфигурации, проект `extension` поверх `base`, `export-edt.mjs` в `extension`. Затем второй запуск `1cedtcli`: `export` конфигурации, `import` и `export` расширения. Затем `.cf`: `/LoadConfigFromFiles` → `/DumpCfg` в той же базе. `.cfe`: отдельная пустая база → `/LoadConfigFromFiles … -Extension` → `/DumpCfg … -Extension`. XML для Конфигуратора (формат 2.20 для 8.3.27) порождает EDT, вручную он не пишется.
  - Свойства `.cf`: имя `ИконкиМетаданных1С`, синоним, комментарий с автором и лицензией, поставщик, версия из `package.json`, режим совместимости 8.3.14 (и расширений тоже), чтобы файл открывался на старых платформах. Собирается самой старой установленной платформой не ниже 8.3.14.
  - Расширение: то же имя, назначение `AddOn`, префикс имён `Метаданные` (с него начинаются все картинки), режим совместимости 8.3.14. Язык «Русский» заимствуется, и связь идёт по имени, а не по UUID базы, поэтому `.cfe` подключается к любой конфигурации с русским языком. Проект расширения пишется вручную по образцу `tools_ui_1c` (`V8ExtensionNature`, `Base-Project` в `PROJECT.PMF`, `objectBelonging Adopted`).
  - Проверка в конце: `.cf` → новая база → XML; `.cfe` → новая пустая база → `/LoadCfg -Extension` → `/UpdateDBCfg -Extension` (расширение применяется к чужой конфигурации) → XML. Все PNG и `manifest.xml` каждой картинки побайтно сравниваются с `dist/1c`, проверяются свойства. Вручную проверено, что оба файла открываются и применяются и в 8.3.27, и в 8.5.1.1529. Объединение `.cf` с конфигурацией и `.cfe` с расширением владелец проверил вручную 15.10.2026, все картинки на месте; сборка его не проверяет, оно интерактивное.
  - Пути: `V8_DESIGNER`, `EDT_CLI`, `EDT_JAVA_HOME`. Без них — `%ProgramFiles%\1cv8\<версия>\bin\1cv8.exe`, последняя установка в `%LOCALAPPDATA%\1C\1cedtstart\installations`, JDK из `%ProgramFiles%\1C\1CE\components`.
- Подводные камни сборки `.cf` и `.cfe`:
  - `1cedtcli` не принимает `-vm`. Java он берёт из `JAVA_HOME` и `PATH`. Java 8 из `PATH` даёт окно «Provided Java does not match the required version 25» прямо на экране владельца, поэтому JDK передаётся через `JAVA_HOME`. Вывод `1cedtcli` в CP866.
  - В файле команд `1cedtcli -file` в кавычках только пути. Команда или значение в кавычках дают «Cannot coerce … to any of []».
  - `[Fatal Error] :1:1: Premature end of file.` в выводе EDT — безвредный шум. Его печатает `org.eclipse.wst.server.core` 1.11.0 на Java 25: `new File("").exists()` теперь `true` (JDK-8346673, eclipse-servertools/servertools#19). Сборка показывает вывод EDT только при ошибке.
  - Количество `containedObjects` зависит от версии платформы: у 8.3.27 их 7, у 8.3.12 (`tools_ui_1c`) 6. При несовпадении Конфигуратор пишет «Узлов ContainedObject должно быть 7». Поэтому `classId` для расширения берутся из базового проекта той же версии.
  - `1cv8` сам разбирает командную строку и не понимает `\"`: в Node нужны `windowsVerbatimArguments` и кавычки вокруг путей вручную. Из Git Bash ключи `/Out` и `/F` превращаются в пути, поэтому платформу из bash вызывать только через PowerShell или Node.
  - У платформ 8.5.4.x установлен только тонкий клиент `1cv8c.exe`, полный `1cv8.exe` есть у 8.5.1.1529.
  - В чистом проекте EDT язык записан в `Configuration.mdo` блоком `<languages uuid="…">…</languages>`, а не ссылкой. `export-edt.mjs` ищет элементы-ориентиры в обеих формах.
- Префикс по умолчанию пустой. Он должен быть идентификатором 1С: буквы, цифры и `_`, первым символом не цифра.
- `dist/`, `node_modules/` и `sources/` в `.gitignore`.

## Окружение

- Минимальная версия Node.js — 20.15 (`engines` в `package.json`): сборка использует `zlib.crc32`. Инструкция по установке для Windows и Linux — в README.
- Windows, Node.js 24. Python: `%LOCALAPPDATA%\Programs\Python\Python313\python.exe` (`python.exe` в PATH — заглушка Microsoft Store), Pillow не установлен.
- Скрипты PowerShell 5.1 с кириллицей сохранять в UTF-8 с BOM, иначе они читаются в ANSI.
